## Candidate foundation

Candidates and employers have separate User/Employer records and authenticated roles. Intern and licensed-scientist stages share one candidate account, preserving documents/history on transitions. Career fields include education, placement, experience, specialties, preferences, availability and relocation. Personal reminders remain private.

Employer talent queries restrict access to previous applicants to that employer. Documents require employer verification and an application relationship. Applicant/talent responses strip the full candidateProfile JSON and return placement stage, leaving the richer professional profile unavailable to employer screening.

`node --test tests/candidate-profiles.test.cjs`: 12/12 passed this review. Tests use mocked dependencies. Hosted deployment, real storage and complete browser journeys were not verified.

## Pilot priorities

1. Add an explicitly selected professional summary for employers and a candidate preview of shared information. Include relevant education, experience, specialties, availability and preferences; exclude reminders and scan metadata.
2. Align server application checks with agreed readiness requirements. app/api/apply/route.ts currently checks only that resumeUrl exists; lib/readiness.ts checks private storage. Profile completeness must not imply verified professional eligibility.
3. Define application-specific document scope, retention and withdrawal. Current document access allows supported current-user document kinds to an approved employer with any application relationship; it is not a submission snapshot. Check continuing access when other applications remain.
4. Validate credential-review labels against expiry, changed documents and review evidence. Exercise cross-account denials, withdrawal and stage transitions in staging.
5. Consider structured employment history and a professional summary. A CV can provide detailed history during the pilot. Public candidate profiles and broad opt-in talent discovery can wait.

Begin the launch audit with these findings; prioritise, implement and re-test rather than delaying the audit until all proposed features exist. No application code, schema, migrations or hosted deployment changed in this review.
